# Восстановление 3D-скорости волейбольного мяча с монокулярной камеры
## Архитектура пайплайна: калибровка → трекинг → сегментация → баллистический фиттинг

---

## 0. Постановка проблемы

Один статичный ракурс не наблюдает глубину напрямую. Любая ошибка в предположении о глубине (Z) умножается проекционным коэффициентом (в вашем случае ~1:5.6 из-за пологого угла: камера Z≈7.5м, X≈-24м) и превращается в метры ошибки по дальности. Ранее опробованные подходы не сработали по конкретным причинам:

| Подход | Почему не сработал |
|---|---|
| Размер bbox YOLO как прокси глубины | Motion blur и сжатие → рамка "дышит", скачки глубины на 1-2 м между кадрами |
| Causal EKF на сырых 2D-центрах | Скачки глубины интерпретируются как удары → пробитие порогов невязки → разрушение трека |
| Клик по кроссовкам (Z=0) для якоря | Ноги игроков часто обрезаны границей кадра при подаче |
| Фиксированная высота съёма (Z=const) | Ошибка ±35 см по факту удара × коэффициент 5.6 ≈ 2 м ошибки по дальности |

**Вывод**: нужен переход от "покадровой оценки по одному шаткому якорю" к "батч-оценке по множеству наблюдений, ограниченной известной физикой".

---

## 1. Калибровка камеры (разовая, для статичной камеры)

### Метод
`cv2.solvePnP` по 6-8 точкам корта с известными реальными координатами (FIVB регламент фиксирует размеры с точностью до см):
- 4 угла площадки
- углы линий нападения
- верх и низ антенн на сетке
- точки крепления сетки к столбам

### Результат
Матрица проекции `P = K[R|t]`, позволяющая:
- проецировать 3D → 2D (`project(P, X,Y,Z) → u,v`) для фиттинга траектории;
- грубо обратно проецировать 2D → 3D при известном одном измерении (например, Z=0 для ступней игрока).

### Важное свойство
Сетка и антенны — это **живые reference-точки во время матча**: каждый пролёт мяча над сеткой (известная высота 2.43 м муж / 2.24 м жен) даёт возможность верифицировать/подстроить калибровку без необходимости видеть разметку пола, которая может быть закрыта игроками.

---

## 2. Трекинг мяча

- YOLO детекция → **не bbox-центр**, а центр аппроксимированного эллипса по маске (если доступна сегментация) или центр с учётом смаза — при motion blur геометрический центр bbox смещён относительно реального центра мяча.
- `box_size_px` не используется как жёсткий вход, а сглаживается (running median, окно 5-7 кадров) и подаётся в итоговый фиттинг как **слабый регуляризатор** с robust loss (Huber/Tukey), а не как источник истины.

---

## 3. Детекция игроков (для channel B, см. ниже)

### Выбор модели для точки контакта
Полноценный skeleton pose (YOLOv8-pose/MediaPipe) избыточен и часто ненадёжен для кистей на дальнем плане (keypoints рук деградируют сильнее всего на низком разрешении). Варианты, которые стоит протестировать на реальной съёмке:

1. Отдельный детектор класса "кисть/рука", если есть данные для дообучения.
2. Fallback-цепочка по confidence: кисть → локоть/предплечье (расширяя радиус проверки с 0.5-0.8 м до 0.8-1.0 м) → bbox верхней трети корпуса игрока.
3. Грубый вариант: весь bounding box игрока целиком как зона-кандидат (менее точно, но устойчивее при низком разрешении).

Заранее не угадать, какой вариант лучше сработает на конкретной съёмке — нужен эмпирический тест.

### Обратная 3D-проекция игрока
Ступни игрока (Z=0) видны гораздо надёжнее, чем ступни подающего в момент удара — отсюда:
- (X,Y) игрока по ступням → обратная проекция при Z=0 (используя ту же матрицу P);
- Z верхней точки контакта (кисть/плечо) — антропометрическая оценка (~1.75-1.9 м) или по высоте прыжка, если детектируется отрыв от пола.

## 4. Сегментация траектории на независимые баллистические отрезки

Это узкое место всей схемы: если сегментация ошибается, МНК получает склеенный кусок из двух парабол и выдаёт гладкую, но неверную скорость. Один сигнал недостаточен — нужна триангуляция минимум по трём каналам.

### Channel A — физическая аномалия (основной сигнал)

Идея: в свободном полёте вертикальная динамика подчиняется `Vz(t) = Vz0 - g·t` — строго линейной функции. Излом этой линии — самый надёжный маркер контакта (горизонтальная динамика зашумлена вращением/сопротивлением воздуха и менее показательна).

```
для каждого кадра t:
    окно = [t-W, t+W]  # W ~ 5-8 кадров
    зафитить локальную параболу на окне
    residual(t) = |наблюдение(t) - модель(t)|
```

Кандидат на событие = резкий локальный пик residual **в центре окна** (не на краях — это отличает реальное событие от постепенного дрейфа калибровки/шума).

### Channel B — пространственное подтверждение через игроков

Channel A даёт кандидатов, но не отличает реальное касание от шумного выброса детектора (особенно у сетки: антенна, трос, блок). Подтверждение:

- Обратная 3D-проекция мяча в окрестности кадра-кандидата (экстраполяция баллистики предыдущего сегмента или широкий доверительный интервал из текущего батч-фита).
- Обратная 3D-проекция кисти/зоны контакта игрока (см. раздел 3).
- **Сравнение расстояния в метрах, а не в пикселях** — критично важно при пологом угле съёмки, где визуальная близость на экране не означает близость в пространстве.
- Поиск не в одном кадре, а **минимума расстояния мяч–кисть по времени в окне ±3-4 кадра** вокруг кандидата (момент контакта часто физически лежит между двумя записанными кадрами).

Событие подтверждается, если A и B совпадают по времени и месту. Кандидат A без подтверждения B — не режем сегмент, интерполируем/игнорируем как шум детектора.

Отдельный случай — **отскок от пола**: подтверждение вместо игрока — Z-координата мяча близка к нулю с сонаправленной сменой знака Vz.

### Channel C — вспомогательный сигнал уверенности

Во время реального контакта мяч часто деформируется на кадре (сплющивание), confidence YOLO проседает/скачет, соотношение сторон bbox меняется. Используется не как самостоятельный триггер (слишком шумно), а как **вес в голосовании** и для уточнения суб-кадровой локализации.

### Итоговое правило голосования

```
Событие (разрыв сегмента), если:
    (A: физический излом Vz(t) выше порога) И
    (
        B: игрок в радиусе от точки контакта в 3D
        ИЛИ
        floor-эвристика: Z≈0 и смена знака Vz
    )
    [опционально усиливается C: просадка confidence/деформация bbox]

Одиночный A без подтверждения → НЕ режем, интерполируем, 
но перепроверяем на уровне 2 (глобальный residual).
```

### Уровень 1 — суб-кадровая локализация точного момента

Грубый интервал события сужается до точного `t_touch` (с точностью до долей кадра):
- фит баллистики отдельно слева и справа от предполагаемого разрыва (на "чистых" кадрах, отступив 2-3 кадра от кандидата в обе стороны);
- поиск точки минимальной суммарной невязки двух моделей (bisection по residual) — это и есть точка контакта.

### Уровень 2 — итеративная валидация (защита от пропущенных касаний)

```
для каждого сегмента после первичной нарезки:
    зафиттить полную МНК-параболу на весь сегмент
    RMSE = невязка по всему сегменту
    если RMSE > порог (например, 0.15 м):
        найти кадр с максимальным точечным residual внутри сегмента
        повторно прогнать channel B на этом кадре
        если подтверждено → разбить сегмент на два, повторить фит
```

Это ловит слабые/быстрые касания (например, лёгкое второе касание при приёме пальцами), которые не поймал channel A на первом проходе — глобальный фит всё равно проявит аномально высокий residual для склеенного сегмента.

## 5. Батч-фиттинг баллистики (замена causal EKF)

Для каждого подтверждённого сегмента:

```
параметры: X0, Y0, Z0, Vx0, Vy0, Vz0 (опционально Cd — коэффициент сопротивления)

minimize (scipy.optimize.least_squares, robust loss):
    Σ_i || project(P, X(t_i; params)) - (u_i, v_i) ||²
    + λ_size · Σ_i Huber( depth_from_bbox_size(t_i) - Z_model(t_i) )   # низкий вес, канал 3

где X(t) — решение баллистики (RK4) с учётом g=9.81 м/с² как жёсткого ограничения масштаба.
```

Почему это устойчивее покадрового EKF:
- 20-30 наблюдений вместо одного шаткого якоря — оптимизатор статистически "выжимает" глубину из формы кривой, а не полагается на единственную точку;
- единичные выбросы (motion blur, детекторный шум) получают меньший вес в сумме по всему сегменту вместо мгновенного разрушения фильтра;
- скорость — это напрямую величина вектора `(Vx0, Vy0, Vz0)` из решения, а не разность соседних зашумлённых позиций.

`км/ч = |V0| (м/с) × 3.6`

## 6. Структуры данных (псевдокод)

```python
@dataclass
class BallObservation:
    frame_idx: int
    t: float                # секунды от начала видео
    u: float                # пиксель X
    v: float                # пиксель Y
    bbox_size_px: float | None
    confidence: float

@dataclass
class PlayerContactCandidate:
    frame_idx: int
    t: float
    hand_uv: tuple[float, float] | None      # None если fallback на локоть/bbox
    hand_source: Literal["hand", "elbow", "torso_bbox"]
    hand_confidence: float
    player_id: int
    feet_uv: tuple[float, float]             # для обратной проекции X,Y при Z=0

@dataclass
class TouchEvent:
    t_touch: float
    frame_range: tuple[int, int]             # окно суб-кадровой локализации
    event_type: Literal["hand_contact", "floor_bounce", "unknown"]
    player_id: int | None
    confidence: float                        # агрегированная оценка A+B+C

@dataclass
class TrajectorySegment:
    observations: list[BallObservation]
    start_event: TouchEvent | None
    end_event: TouchEvent | None
    fitted_params: dict | None   # X0,Y0,Z0,Vx0,Vy0,Vz0,Cd после МНК
    rmse: float | None
    speed_kmh: float | None


def segment_trajectory(observations: list[BallObservation],
                        players: dict[int, list[PlayerContactCandidate]],
                        P: np.ndarray) -> list[TrajectorySegment]:
    # 1. Channel A: скользящее окно, локальный фит, поиск пиков residual по Vz(t)
    candidates = detect_physical_anomalies(observations, window=7)

    # 2. Channel B: подтверждение через 3D-близость к игроку или floor-эвристику
    confirmed = []
    for c in candidates:
        ball_3d = estimate_ball_3d_at(c.t, observations, P)
        if is_floor_bounce(ball_3d):
            confirmed.append(TouchEvent(c.t, c.frame_range, "floor_bounce", None, c.score))
            continue
        best_player, dist = find_nearest_player_hand_3d(c.t, players, P, window=4)
        if dist < THRESHOLD_METERS:
            confirmed.append(TouchEvent(c.t, c.frame_range, "hand_contact", best_player, c.score))

    # 3. Суб-кадровая локализация (bisection по невязке左/right фитов)
    confirmed = [refine_subframe(e, observations) for e in confirmed]

    # 4. Нарезка на сегменты
    segments = split_by_events(observations, confirmed)

    # 5. Уровень 2: глобальная валидация и доразбиение при высоком RMSE
    segments = validate_and_resplit(segments, players, P)

    return segments


def fit_ballistics(segment: TrajectorySegment, P: np.ndarray) -> TrajectorySegment:
    def residuals(params):
        X0, Y0, Z0, Vx0, Vy0, Vz0 = params[:6]
        res = []
        for obs in segment.observations:
            X_t = integrate_rk4(X0, Y0, Z0, Vx0, Vy0, Vz0, obs.t, g=9.81)
            u_pred, v_pred = project(P, X_t)
            res.append(u_pred - obs.u)
            res.append(v_pred - obs.v)
            if obs.bbox_size_px is not None:
                depth_pred = X_t.z  # или расстояние до камеры
                depth_from_size = FOCAL_PX * BALL_DIAMETER_M / obs.bbox_size_px
                res.append(LAMBDA_SIZE * huber(depth_from_size - depth_pred))
        return res

    result = scipy.optimize.least_squares(residuals, x0=initial_guess(segment),
                                           loss="huber", f_scale=1.0)
    segment.fitted_params = unpack(result.x)
    segment.rmse = compute_rmse(segment, result)
    Vx0, Vy0, Vz0 = result.x[3:6]
    segment.speed_kmh = np.linalg.norm([Vx0, Vy0, Vz0]) * 3.6
    return segment
```

## 7. Известные ограничения подхода

- **Несколько игроков вплотную у сетки (блок 2-3 человека)**: обратная 3D-проекция ступней/pose может давать неоднозначность даже после проекции. Атрибуция "кто коснулся" в этом случае — best-guess, не hard constraint для самой нарезки сегмента (нарезка полагается сильнее на channel A + floor-эвристику).
- **Полностью монокулярная система принципиально не может** сравниться по надёжности с двухкамерной триангуляцией — при жёстком ограничении в одну камеру описанная схема (калибровка по корту + батч-баллистика с g как источником масштаба) — практический потолок точности для одного ракурса.
- Точность фиттинга напрямую зависит от качества калибровки P (раздел 1) — стоит предусмотреть периодическую самопроверку по известной высоте сетки как встроенный тест на дрейф калибровки.

## 8. Итоговый пайплайн (сводно)

1. Разовая калибровка камеры (`solvePnP` по корту) → `P`.
2. YOLO-трекинг мяча + сглаженный центр (эллипс/учёт смаза).
3. Параллельный трекинг игроков (кисть/локоть/bbox с fallback-цепочкой).
4. Сегментация: Channel A (физическая аномалия по Vz) → Channel B (3D-близость к игроку/пол) → Channel C (доп. вес confidence) → суб-кадровая локализация → нарезка.
5. Уровень 2: глобальная валидация RMSE каждого сегмента, доразбиение при необходимости.
6. Батч МНК-фиттинг баллистики на каждый сегмент (RK4 + g=9.81, `bbox_size_px` как слабый регуляризатор).
7. Скорость = `|V0| × 3.6` км/ч.
8. (Опционально) RTS-сглаживание поверх для визуализации покадровой траектории.
